# 3.1 Abordagem de Desenvolvimento

O BiblioTech é desenvolvido de forma **iterativa e incremental**. Cada ciclo produz uma seção deste documento, na ordem em que a análise pede. Primeiro vem o que o sistema é (4.1). Depois vêm o que ele precisa fazer (4.2.1 e 4.2.2) e como ele é por dentro (4.2.3). O comportamento vem a seguir (4.2.5 e 4.2.4), e depois o que ele guarda (4.2.6) e como aparece para quem usa (4.2.7). A arquitetura (3.3) fica para o fim, quando todas as partes já existem.

No fim de cada ciclo, a seção nova é conferida contra as anteriores. Todo caso de uso precisa ter vindo de um requisito, e toda classe precisa aparecer em algum caso de uso. Quando algo não bate, a correção é feita na seção de origem, e a nova versão fica registrada no repositório.

A escolha tem dois motivos. Cada seção depende da anterior, e fazer o documento inteiro de uma vez deixaria os erros para o fim, quando corrigir custa mais. A cliente também consegue conferir cada parte antes da seguinte, o que no modelo em cascata só aconteceria com o documento pronto. Como o projeto tem uma pessoa só, as cerimônias do Scrum, como a reunião diária, ficam de fora. Do Scrum fica a ideia central de trabalhar em ciclos curtos, com uma entrega que dá para revisar.
